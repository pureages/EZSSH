EZSSH 用户使用手册

干净、高效、可视化的自托管中心化 SSH Web 网关 · 版本 v0.0.1 · 更新日期 2026-08-04

1. 产品简介

EZSSH 是一个自托管的中心化 SSH Web 网关：在浏览器中登录后进入一个类 Windows 的 Web 桌面，以「窗口化应用」的方式统一管理你名下所有 Linux 服务器。它仅依赖目标机的原生 SSH / SFTP 服务，无需在服务器上安装任何 Agent，也不开放额外端口，安全可控。

🖥️ Web 桌面深色玻璃拟态桌面，窗口可拖拽 / 缩放 / 最小化 / 全屏 / 关闭；ESC 一键关闭当前窗口。
📦 十大应用终端、文件管理器、任务管理器、Docker、防火墙、直链下载、世界地图、一键命令、网站管理、设置。
🔐 安全设计凭据 AES-256-GCM 加密、登录验证码、TOFU 主机密钥确认、操作审计、安全路由。
🌐 国际化默认 English，支持简体中文一键切换，偏好保存在服务器端。

架构概览

系统由两部分组成：

  • 网关后端（Go）：提供 REST + WebSocket 服务，负责认证、凭据保险库、SSH 连接池（ConnectionHub）、SFTP 文件操作以及各类管理逻辑，数据持久化在 SQLite。
  • Web 前端（React + Vite）：浏览器中的桌面外壳与各窗口应用，通过 HTTP / WebSocket 与网关通信。
本手册面向系统管理员与日常使用者，从部署启动、桌面操作到每个应用的使用方法均有说明，并附常见问题。

2. 快速开始

2.1 环境要求与构建运行

组件要求
运行环境Windows / Linux / macOS，Go 1.22+（go.mod 会自动切换 toolchain）
被管理服务器任意支持 SSH 的 Linux（Ubuntu / Debian / CentOS / Alpine 等）；部分应用（防火墙）基于 ufw
Node.js（可选）仅自定义前端开发时需要，用于重新构建 web/dist

构建并运行网关（后端可直接托管前端产物 web/dist）：

# 首次构建并运行
go build -buildvcs=false ./cmd/ezssh
./ezssh.exe          # Windows

# 或直接运行
go run ./cmd/ezssh

若修改了前端代码，需先构建前端产物：

cd web
npm install
npm run build

开发态可前后端分离：终端 A 运行 go run ./cmd/ezssh；终端 B 运行 cd web && npm run dev（默认 5173 端口，前端热更新）。

2.2 首次初始化与登录

  1. 浏览器访问 http://127.0.0.1:49466。
  2. 首次进入会显示初始化向导：创建管理员账号口令（至少 8 位）。口令是凭据保险库的根密钥来源，请务必牢记。
  3. 默认界面语言为 English；如需中文，登录后在「设置 → 语言」切换。
  4. 输入口令登录。登录时保险库自动解锁；若登录失败一次，需输入图形验证码。

2.3 添加服务器

  1. 登录后进入「主机管理」页，点击新增主机。
  2. 填写主机名、IP / 域名、SSH 端口（默认 22）、用户名，认证方式可选密码或私钥。
  3. 凭据保存时经 AES-256-GCM 加密入库（保险库）。表单内置「🛠 测试连通性」按钮，可先验证配置再保存。
  4. 保存后点击「进入桌面」，即可在 Web 桌面上看到该服务器图标。

3. Web 桌面使用

3.1 窗口管理

  • 每个应用以窗口形式打开，可拖拽标题栏移动、拖拽边角缩放。
  • 窗口右上角为 Windows 风格按钮：最小化 / 最大化（全屏）/ 关闭。
  • 点击窗口任意位置将其置为当前激活窗口（置顶）。
  • 选中窗口后按 ESC 可关闭该窗口；各应用内部的子窗口 / 弹窗同样支持 ESC 关闭（优先级高于主窗口）。

3.2 服务器图标

  • 双击图标 → 打开该服务器的文件管理器。
  • 左键拖动图标可自定义位置（可开启自动对齐），位置保存在浏览器。
  • 支持框选多选图标。
  • 右键图标弹出菜单：打开 终端 / 文件管理器 / 任务管理器 / Docker / 防火墙 / 直链下载，或编辑服务器。
  • 图标左侧显示系统 Logo（自动识别发行版）与国家/地区国旗（按 IP 地理位置）。
  • 图标下方实时显示三行微型监控：CPU|内存|硬盘、上传|下载速率、总上传|总下载。可在设置中隐藏；采集失败时显示「已离线」。
  • 右键桌面空白处：刷新 / 添加服务器 / 设置 / 自动对齐 / 退出登录。

3.3 任务栏与应用中心

屏幕底部为任务栏：显示已打开窗口的角标，点击可恢复或切换。任务栏 🪟 按钮打开应用中心，其中包含全局应用：世界地图、添加服务器、设置、直链下载、一键命令、网站管理。服务器相关的应用（终端、文件管理器等）需从服务器图标右键菜单或应用中心中选择对应服务器后打开。

3.4 ESC 关闭与后台进度

  • ESC 关闭：选中任意窗口或子窗口后按下 ESC，按「子窗口/弹窗 → 当前窗口」的优先级依次关闭。
  • 后台进度：长耗时操作（Nginx 安装、网站部署、证书签发、文件复制粘贴等）的进度窗口可点击最小化折叠为任务栏角标，操作在后台继续执行——成功后角标自动收起；失败则自动还原窗口展示错误。点击角标可随时还原查看实时进度。

4. 应用使用指南

4.1 终端

基于 xterm.js 的全功能 SSH 终端：

  • 支持多个终端窗口同时打开、窗口自适应大小。
  • 终端输出中的链接可点击。
  • 支持常见快捷键（复制粘贴、中断等）与终端尺寸变化同步。

4.2 文件管理器

  • 目录浏览：地址栏输入路径回车跳转，支持返回 / 前进 / 上级 / 刷新。
  • 上传 / 下载：拖拽或按钮上传，均带实时进度；下载支持断点续传（Range）。
  • 在线编辑：文本文件双击在线编辑并保存。
  • 右侧预览面板：文本可编辑保存；图片可缩放 / 旋转；视频可播放。
  • 基本操作：新建文件/目录、重命名、删除（递归）、修改权限（chmod）。
  • 右键菜单：空白处右键新建、文件右键复制/剪切/粘贴/编辑/下载/权限等。
  • 复制 / 剪切 / 粘贴：
    • 同服务器：直接粘贴（服务端移动/复制）。
    • 跨服务器：可选择直连传输（源机 scp 直推，数据不经网关）或中转传输（网关双 SFTP 转发）；均带实时进度且可取消。

4.3 任务管理器

参考 Windows 任务管理器的双页签设计：

  • 硬件：左侧硬件列表 + 右侧详情（系统 / CPU / 内存 / Swap / 硬盘 / 网络），含发行版、主机名、运行时长、CPU 型号与核心数、虚拟机识别（DMI 检测）。
  • 性能：CPU / 内存 / Swap / 负载 / 磁盘 / 网络实时图表（ECharts）；概览含硬盘占用、下载/上传速率与总量。
  • 进程：进程列表、按关键字搜索、发送 TERM / KILL 信号。

4.4 Docker 管理

  • 容器 / 镜像：列表查看、启动 / 停止 / 重启 / 删除容器、删除镜像。
  • 日志 / stats：查看容器日志与实时资源统计；容器详情 inspect。
  • Docker 一键安装：目标机未安装 Docker 时，可一键安装（自动识别包管理器，流式输出过程）。
  • 应用市场：内置常用镜像模板，填写端口 / 环境变量 / 挂载即可创建容器；支持自定义 docker run；支持目标机不兼容时以配置文件注入环境变量。

4.5 防火墙管理

基于 ufw（Ubuntu 默认可用）：

  • 查看防火墙状态 / 版本 / 启用情况，一键开启 / 关闭。
  • 规则列表（解析自 /etc/ufw/user.rules），支持禁 IP / 允许 IP / 禁端口 / 允许端口 / 端口范围 / 全部流量。
  • 开启防火墙前自动放行 SSH 端口（自动探测实际 SSH 端口），避免把自己锁在门外。

4.6 直链下载

基于 aria2 的免登录直链下载器：

  • 一键安装 aria2（自动识别 apt / dnf / yum / apk，流式输出安装过程）；daemon 常驻目标机（/tmp/ezssh_aria2）。
  • 支持 HTTP / HTTPS 直链与 BitTorrent 种子下载。
  • 保存目录可在目标机浏览器上实时浏览选择；保存文件名可自定义。
  • 任务可暂停 / 继续 / 取消，实时显示进度、速率与剩余时间。

4.7 世界地图

基于 ECharts 世界地图，按 IP 地理位置聚合展示全部服务器：

  • 绿色光点 = 在线（光点大小随 CPU 负载，点击查看详情），灰色 = 离线。
  • 悬停 tooltip 显示在线率、负载、速率等信息。

4.8 一键命令

  • 保存常用的服务器管理命令（如更新系统、查看日志、重启服务等）。
  • 一键将命令批量分发到多台服务器执行，统一查看输出结果。

4.9 网站管理

网站管理是发布 Web 站点与 HTTPS 证书的一站式应用（基于 Nginx + acme.sh + Let's Encrypt），支持跨服务器浏览与部署。打开应用后先在上方选择一台服务器（Linux）。

4.9.1 安装 Nginx

若所选服务器未安装 Nginx，页面顶部会出现提示横幅，点击一键安装 Nginx：自动识别 apt / dnf / yum / apk 安装、设置开机自启、放行 80/443 端口，全程流式输出。也可在建站保存时按提示一键安装。

4.9.2 新建站点

  1. 点击右上角添加网站，选择部署服务器（新建时可改）、填写站点名称、分组（可选）与域名（多个用逗号分隔，第一个为主域名）。
  2. 选择站点类型：
    类型说明需填写
    静态网站托管静态 HTML 页面网站根目录（默认 /opt/ezssh/apps/WebManager/www/主域名）
    反向代理转发到后端服务（Node/Java/Python 等）代理地址，如 http://127.0.0.1:8080
    重定向301 跳转到新地址目标 URL，如 https://new.example.com
  3. 勾选 启用 SSL（需先为域名签发证书，见 4.9.4）。勾选时会实时检测证书是否已安装并显示到期时间。
  4. 保存后自动部署：生成 nginx 配置 → nginx -t 校验 → reload。静态站点若根目录不存在，会自动创建目录并写入默认首页（index.html，内容随界面语言中/英）。
站点创建后可直接在浏览器新标签打开域名预览。若勾选了 SSL 但证书尚未安装，部署会自动降级为 HTTP 并在结果中提示，不会失败。

4.9.3 站点管理

  • 列表按服务器 / 分组过滤，显示域名（可点击新标签打开）、类型、SSL 状态、分组、启用状态。
  • 操作列：查看文件（打开该服务器文件管理器并进入网站根目录）、编辑、证书、部署（重新部署单站点）、删除。
  • 启用 / 停用：停用会移除服务器上的 nginx 配置并 reload；启用则重新部署。
  • 删除：出于安全，需输入与域名完全一致的内容方可确认。删除会移除远端 nginx 配置、reload，并清理该域名的证书（acme.sh 移除 + 删除证书记录）。

4.9.4 签发 Let's Encrypt 证书

  1. 在「证书」页签点击签发证书，选择验证方式：
    • HTTP 验证（webroot）：要求域名已解析到该服务器且 80 端口公网可达。
    • DNS 验证（Cloudflare，推荐）：要求先新增一个 Cloudflare DNS 账户（见下），对泛解析 / 纯内网域名也适用。
  2. 填写域名（默认取站点主域名）、注册邮箱（可选，用于到期提醒）。
  3. 点击签发，全程流式显示 acme.sh 输出；成功后证书安装到 /etc/nginx/ssl/主域名/ 并 reload nginx，记录到期时间。
  4. 回到站点，勾选 SSL 并重新部署，即可启用 HTTPS。

4.9.5 DNS 账户管理

「证书」页签内的DNS 账户弹窗可管理 Cloudflare API Token（需 DNS 编辑权限）。Token 经 AES-256-GCM 加密存储，列表仅显示是否已配置。签发 DNS 证书时从中选择账户。

4.9.6 续签与到期监控

  • 自动续签：acme.sh 在签发时已写入服务器 cron（主路径）；网关另有兜底循环，每 12 小时检查一次，到期前 30 天自动续签。
  • 手动续签：证书状态到期前可随时点击「续签」强制刷新。
  • 同步：点击后从服务器读取证书实际到期时间并更新记录（若证书未安装到稳定路径会提示去续签）。
  • 删除：仅删除本系统内的证书记录，远端 acme.sh 证书保留（删除网站时会一并彻底清理）。

5. 安全特性

  • 凭据保险库：主机密码 / 私钥以 AES-256-GCM 加密入库，密钥由登录口令经 Argon2id 派生，重启后需重新登录解锁。
  • 修改口令重加密：改密时用新口令派生新密钥并重加密全部主机凭据，旧口令无法解密。
  • 登录验证码：某 IP 登录失败一次后要求输入 SVG 验证码（一次性、5 分钟过期）；失败 5 次/分钟则锁定 5 分钟。
  • 自定义登录路由：可在「设置 → 安全」修改登录页地址（如 /secret-admin），隐藏登录入口。
  • TOFU 主机密钥确认：首次连接记录远端主机密钥指纹，后续连接校验一致，防止中间人替换。
  • 高危操作审计：登录 / 连接 / kill / 删除容器 / 改密 / 改设置等均写入审计日志。
  • Web 安全：终端输出仅经 xterm 渲染不入 DOM（防 XSS）；SQL 参数化；验证码 SVG 由后端生成。

设置应用

  • 个性化：上传桌面背景（PNG / JPG / GIF / WebP，可恢复默认渐变）；桌面图标大小（60%–150%）；图标监控文字大小（9–16px）与颜色（逐项自定义）。
  • 桌面：隐藏 / 显示图标监控。
  • 安全：修改密码；安全路由。
  • 语言：界面语言下拉（简体中文 / English，默认 English，偏好存服务器端，任何设备一致）。
  • 关于EZSSH：版本、作者、GitHub 链接。

6. 部署与运维

6.1 环境变量

变量默认值说明
EZSSH_LISTEN127.0.0.1监听地址
EZSSH_PORT49466监听端口
EZSSH_DATAdata数据目录（数据库等所有持久化数据）
EZSSH_DBdata/ezssh.dbSQLite 文件路径（显式指定则优先）
EZSSH_MASTER_KEY空注入主密钥，跳过「登录时解锁保险库」

6.2 Docker 部署

docker build -t ezssh .
docker run -d --name ezssh -p 49466:49466 \
  -v ezssh-data:/app/data \
  ezssh
  • 数据（数据库 + 加密凭据）持久化在 /app/data 卷。
  • 默认监听 0.0.0.0:49466，可用 -e EZSSH_PORT=xxx 覆盖。

6.3 数据目录与备份

  • 所有持久化数据统一收纳在 data/ 目录，数据库即 data/ezssh.db。
  • 旧版本根目录的 ezssh.db 会在首次启动时自动迁移到 data/（非破坏性复制，旧文件保留，确认无误后可手动删除）。
  • 备份 / 迁移：Docker 部署时把宿主机的 ./data 映射到容器的 /app/data 即可完成备份/迁移。

6.4 公网部署建议

默认监听 127.0.0.1。公网部署强烈建议置于 Caddy / Nginx 之后并启用 HTTPS；不要直接暴露裸 HTTP 到公网。

7. 常见问题（FAQ）

Q1：首次访问提示初始化，口令要求是什么？

管理员口令至少 8 位。该口令同时用于派生凭据保险库密钥，请务必牢记；忘记后将无法解密已保存的主机凭据。

Q2：登录时提示需要验证码？

某 IP 登录失败一次后即要求输入图形验证码，连续失败会临时锁定。稍候重试即可。

Q3：重启网关后主机全部「离线」/ 凭据无法解密？

保险库默认在网关重启后锁定，需重新登录解锁；连接也会随主机在线后自动惰性重连。

Q4：网站管理部署时提示「SSL 已开启但证书尚未签发/安装」？

该域名证书未安装到 /etc/nginx/ssl/域名/fullchain.pem。请先在「证书」页签发或续签，或在站点 SSL 处查看证书检测状态确认就绪后再部署。未就绪时系统会自动降级为 HTTP 部署，不会报错。

Q5：签发证书失败 / 提示「Domains not changed. Skipping.」？

acme.sh 检测到该域名已有证书会跳过。系统在重签时会自动追加 --force 强制重新签发；若仍失败，请检查输出中 DNS 解析、Cloudflare Token 权限、80 端口可达性等。

Q6：网站管理「查看文件」打开的目录与实际不符？

静态站点会进入其网站根目录（自定义 root_dir 或默认 /opt/ezssh/apps/WebManager/www/主域名）；代理/重定向站点进入默认网站目录。若地址栏与文件列表不一致，点击刷新即可。

Q7：文件跨服务器复制如何选择传输方式？

复制/剪切后到目标服务器粘贴时，可选「直连传输」（源机 scp 直推，数据不经网关，速度快）或「中转传输」（网关双 SFTP 转发，源机无法直连目标机时使用）。

Q8：如何修改登录页地址隐藏入口？

登录后在「设置 → 安全 → 安全路由」修改，例如 /secret-admin。修改后旧地址失效。

Q9：防火墙开启后连不上服务器？

系统会在开启前自动放行实际 SSH 端口；若仍无法连接，请检查是否修改过 SSH 端口且该端口未被探测到。可先在「防火墙」中确认 22/自定义端口已放行。

Q10：前端构建产物在哪？如何只更新前端？

前端构建产物在 web/dist，后端直接托管。更新前端只需 cd web && npm install && npm run build 后重启后端即可。

Q11：终端 Agent 提示「验证码错误或已过期」/ 登录失败？

同一 IP 近期（5 分钟内）有登录失败会触发验证码校验，而终端 Agent 无法识别验证码。等待约 5 分钟自动解除，或执行 ezssh stop 后 ezssh start 重启服务清除内存中的失败记录。若忘记密码，可在浏览器（或 Agent 菜单 3）中修改。

8. 终端 Agent（ezssh 命令）

8.1 简介

EZSSH 附带一个纯终端的后台管理 Agent（cmd/ezcli，产物为 ezssh）。它面向「不想先开浏览器」的使用场景：运行安装脚本后服务即后台运行，之后随时输入 ezssh 即可调出交互式管理菜单，查看运行状态、账号信息、修改密码与登录路由、启停服务，全程无需打开浏览器。

Agent 完全走现有 REST API（/api/init、/api/login、/api/init-status、/api/settings、/api/change-password），API 路径固定，不受自定义登录路由影响。

8.2 安装

方式一：一键安装脚本（推荐）。脚本自动检测平台/架构，编译服务端 ezsshd 与 Agent ezssh 两个二进制；若本机有 node/npm 且存在 web/ 目录，还会一并构建前端界面：

bash scripts/install.sh

产物安装到 /usr/local/bin（root 用户且可写时）或 ~/.local/bin；后者不在 PATH 时脚本会提示添加。Windows（Git Bash / msys）同样适用，产物为 ezsshd.exe / ezssh.exe。

方式二：手动构建：

go build -buildvcs=false ./cmd/ezcli     # Agent（ezssh）
go build -buildvcs=false ./cmd/ezssh     # 服务端守护进程（ezsshd）

8.3 初始化向导（ezssh setup）

运行安装脚本后会自动进入初始化向导；也可随时手动执行 ezssh setup。逐项提示，直接回车使用默认值：

项目默认值说明
管理员账号admin1–64 个字符
管理员密码admin123456至少 8 位，需二次确认
登录路由/login以 / 开头，不含空格/#/?
监听端口494661–65535
服务端程序自动探测优先 EZSSHD 环境变量 → 与 ezssh 同目录 → PATH 中的 ezsshd
数据目录~/.ezssh/data服务端数据库等持久化数据

向导随后自动完成：后台启动服务并轮询健康 → 首次使用自动创建管理员账号（已初始化则跳过，不改动既有数据）→ 设置登录路由 → 打印访问地址与账号信息。

8.4 交互式管理菜单（ezssh）

在终端输入 ezssh 即出现菜单：

EZSSH 管理终端 v0.0.1
服务: http://127.0.0.1:49466    状态: 运行中 (PID 1234)

  1) 运行状态      2) 查看账号信息
  3) 修改账号密码  4) 修改登录路由
  5) 停止服务      6) 启动服务
  0) 退出
  • 1 运行状态：PID、HTTP 健康、版本、初始化状态、保险库解锁状态、登录路由、界面语言。
  • 2 查看账号信息：账号、密码、登录路由、访问地址（优先读取服务端实际登录路由）。
  • 3 修改账号密码：输入旧密码（回车默认本地已存值）、新密码并确认；改密成功后自动同步本地配置。改密会触发服务端对全部主机凭据的重加密。
  • 4 修改登录路由：输入新路由（校验规则与服务端一致），立即同步服务端并更新本地配置。
  • 5/6 停止/启动服务：后台进程管理（PID 文件 + HTTP 健康探测判活，跨平台可靠）；启动后轮询等待服务就绪。
  • 0 退出。非法输入循环重询。

8.5 一次性子命令

便于脚本调用：ezssh status / ezssh account / ezssh passwd / ezssh route / ezssh start / ezssh stop。其中 passwd 与 route 仍以交互方式接收输入（避免密码出现在命令行参数中）。

8.6 配置文件与安全提示

  • 配置文件默认 ~/.ezssh/agent.json，可用 --config <path> 指定。
  • 密码以明文存储于该文件（权限 0600，仅本用户可读），用于「查看账号信息」与自动登录；请勿将配置文件外泄。
  • 若不希望明文密码落盘，可删除配置中的 password 字段；「查看账号信息」将不再显示密码，需要登录的操作改为手动输入。
  • 服务日志：~/.ezssh/server.log；PID 文件：~/.ezssh/server.pid。
