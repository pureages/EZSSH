# EZSSH v0.0.7-2

> 发布日期：2026-09-14

本版本聚焦 **证书签发能力增强**（多域名 + 泛域名）与 **安全路由加固**（不泄露入口 + 防扫描）。

---

## ✨ 新增功能

### 1. 证书签发支持多域名（SAN）
- 「网站管理 → 证书 → 签发证书」的域名输入框改为多行输入：**每行一个或用逗号分隔**，可一次性为多个域名签发同一张证书（最多 20 个）。
- 输入时实时显示解析后的域名标签，**第 1 个标 ★ 即为主域名**；主域名决定 `acme.sh` 证书目录与 `/etc/nginx/ssl/<主域名>/` 安装路径。
- 续签、删除、证书状态读取均按主域名处理，SAN 会一并续期。
- 选择「关联网站」时会自动填入该站点的**全部**域名（此前只填主域名）。
- 证书列表显示主域名 + `+N 个域名`（悬浮可看完整列表）。

### 2. 证书签发支持泛域名（Wildcard）
- 支持 `*.example.com` 形式的泛域名。
- 泛域名**自动强制使用 DNS 验证**（HTTP-01 无法验证泛域名）：选择泛域名后验证方式自动切换为 DNS 并禁用 HTTP 选项，输入框下方给出提示。
- 网站（Nginx `server_name`）同样支持配置泛域名，泛域名证书可直接用于站点；建站表单已补充说明。
- 删除网站时会按「证书覆盖的域名列表是否包含该站点域名」清理关联证书。

## 🔒 安全增强

### 安全路由不再通过接口泄露 + 防扫描
- **公开接口不再下发安全路由值**：`GET /api/init-status` 已移除 `login_route` 字段（此前任何人读取该接口即可得知隐藏的登录入口）。安全路由的值只通过**需登录**的 `GET /api/settings` 提供给设置页。
- 新增 `POST /api/route-check`：前端把「当前访问路径」交给服务端，服务端只回答「该路径能否展示登录页」，**不返回、也无法推断出安全路由本身**（常量时间比较）。
- **枚举限流**：路由校验失败按 IP 限流（5 分钟内失败 30 次 → 429），防止暴力枚举入口；限流计数与登录失败计数**相互独立**，避免攻击者用错误路径把管理员锁在登录之外。默认 `/login` 的失败不计入（启用安全路由后它必然不匹配，避免正常刷新触发限流）。
- **访问首页不再自动跳转到安全路由**：访问首页 / 默认地址 / 任意无效路径时统一落到默认 `/login` 并显示「路由错误」页，**必须手动输入完整地址（形如 `#/secret-admin`）**才能打开登录页。
- 附带效果：扫描者在首页只能看到一个通用 SPA 外壳，其它路径返回 404，`/api/settings` 返回 401。
- `ezcli` 的 `status` / `account` 原先从公开接口读取该值，已改为登录后读取 `/api/settings`（失败时回落本地配置）。

> 说明：安全路由定位为**隐藏入口 + 防扫描**，不是认证因子——登录时用户仍然只需输入用户名与密码。

## 📦 安装方式

**一键安装（Linux / macOS / Windows(msys)）**

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/pureages/EZSSH/main/scripts/install.sh)
```

**Docker**

```bash
docker run -d --name ezssh -p 49466:49466 \
  -v ezssh-data:/app/data \
  pureages/ezssh:0.0.7-2
```

**发布产物**

- `ezssh-0.0.7-2-linux-amd64.tar.gz`
- `ezssh-0.0.7-2-linux-arm64.tar.gz`

## ⬆️ 升级注意

- 数据库结构无变更，直接替换二进制 / 镜像即可。
- 若此前已设置安全路由，升级后访问首页将不再自动跳转到该地址（会显示「路由错误」），请使用完整地址（含 `#`）访问。
- 若忘记了安全路由，需在网关数据目录的 SQLite `settings` 表中修改 `login_route`（或临时改回 `/login`）。
